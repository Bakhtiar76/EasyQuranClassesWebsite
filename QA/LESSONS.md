# Design parity lessons

1. Verify current state rather than assuming dated task notes still apply: Docker was already running.
2. Existing user changes rename the reference JPEGs and add `Website Layout.png`; preserve these and do not stage deletions incidentally.
3. CLI and web PHP can see different `WORDPRESS_CONFIG_EXTRA` values with the official Docker image. Confirm environment as well as URL before local writes.
4. Rebuild with `--user=1` and verify distinctive saved content. Regenerated inline dividers require rebuilding every page; CSS masks do not.
5. The actual composite is992×1586, and individual JPEGs use different native widths. Record native coordinates and normalized canvas fractions; do not assume any file itself is1920px wide.
6. A localhost-only screenshot guard must inspect redirects before following them. Checking the final URL is too late. The runner now fetches redirects with maxRedirects0 and checks every next URL before fetching it.
7. Baseline captures must include the original fonts. The legacy site fetched Google Fonts; baseline used a narrow `--allow-fonts` exception. Subsequent captures use self-hosted fonts with no exception. Reduced motion makes screenshot states deterministic; normal motion is tested separately.
8. Existing hero media already contains a gold frame; teachers are~220px and blog sources only163px tall. Do not mistake baked photo decoration for the live SVG silhouette, and do not claim these small crops are licensed original photography.
9. A passing viewport list can miss a narrow failure between breakpoints: the intermediate scan found footer overflow at1000px. Fix the content breakpoint and repeat the scan.
10. A manually supplied aria-label can disagree with concatenated visible text. Put real whitespace between wordmark lines and let its accessible name derive from the visible text. Test with Lighthouse as well as visual review.
11. (`claude-opus-5`) The section JPEGs are crops at DIFFERENT zoom levels, so a canvas fraction is only comparable within one file: the same content column measures 84.4% in `Home.jpeg`, 91.9% in `pricing.jpeg` and 94.4% in `Teachers.jpeg`. Only `Home.jpeg` carries both the header bar and a content-width element on one canvas, so it is the only file that can fix the content-to-chrome ratio. Never average fractions across files.
12. (`claude-opus-5`) Derive type size from GLYPH WIDTH, not from an assumed ascender ratio. Estimating the hero H1 from its measured ascender gave 86px; measuring the actual rendered width of the actual string against the reference's own line width gave 79px. The width method uses the real font metrics, the ascender method assumes them.
13. (`claude-opus-5`) The child theme versioned its CSS by theme version, which only changes on release, so mid-iteration edits were served from browser cache. This presents as a half-applied page — `tokens.css` refreshed while `components.css` had not, so new custom properties were live but the rules consuming them were not, which reads exactly like a specificity bug. `functions.php` now falls back to `filemtime()` when `wp_get_environment_type()` is `local`.
14. (`claude-opus-5`) Icons render through `<use>`, so the referenced symbol sits in a shadow tree: CSS from the page cannot reach its inner paths, and a `fill="none"` presentation attribute inside the symbol beats any inherited fill. A filled variant has to be a symbol of its own in `build-icon-sprite.mjs` (`star-filled`), not a CSS override.
15. (`claude-opus-5`) `repeat(auto-fit, minmax(min(150px, 100%), 1fr))` resolved inconsistently inside an Elementor HTML widget: the grid settled at two columns while the widget wrapper kept the height of the four-row single-column layout, leaving ~130px of dead space. Explicit `grid-template-columns` per breakpoint is deterministic; prefer it inside Elementor widgets.
16. (`claude-opus-5`) Elementor gives every container 10px of inline padding; nested two deep that is 40px off the usable width, which is enough to break a measured line-break. Zero it on any container whose width you have measured against the reference.
17. (`claude-opus-5`) Redirecting WP-CLI output to `/tmp/...` from Git Bash silently writes nothing (the path resolves outside the MSYS root and the file ends up empty), which looks exactly like a failed `--user=1` save. Write verification dumps into the repo's own gitignored scratch dir instead.
18. (`claude-opus-5`) **Never mix fixed px and fluid units in one design system.** The client's design is proportional (every dimension a fixed fraction of a 1307px canvas). Converting only the values you happen to be fixing leaves the page *worse* than leaving it alone: a correctly-scaled 79px H1 above an unscaled 18px paragraph reads as broken in a way neither value does by itself. `--eqc-u` (one unit = one px on the reference canvas) now drives every size token, so measuring the reference and writing the value is a direct transcription.
19. (`claude-opus-5`) A reference screenshot's own x margins can be asymmetric (Home.jpeg: 105 left, 83 right) because it includes a scrollbar. Compare widths and y positions directly, but compare x against a *centred* column — matching the raw x would be matching a capture artefact.
20. (`claude-opus-5`) Some reference line breaks cannot be reproduced by any single max-width: the trust tiles break at ~105 native px in one column and ~150 in another. Where that happens the break is content, not styling — `eqc_trust_tile()` takes `|` as an explicit break.
21. (`claude-opus-5`) Elementor adds 10px of inline padding at every container nesting level. Nested three deep that is 30px off a column whose width you measured against the reference, and it silently broke a line break. Zero it on any container you have measured.
22. ~~(`claude-opus-5`) A proportional scale needs a floor that is applied in a MEDIA QUERY, not as `max()` on the token.~~ **SUPERSEDED by #36 — this was wrong and caused a real defect.** A breakpoint-bounded floor only holds on one side of the breakpoint: it left a 6px discontinuity at exactly 1100px (captions jumped 9.8px → 14.0px across one pixel of viewport width) and no floor at all from 1101–1600px, where mainstream laptops live and body copy ran 10.1–14.7px. The premise that a `max()` "would change the rendering at the reference width" was itself the tell that the sizes were wrong at the reference width too.
23. (`claude-opus-5`) An ad-hoc Playwright `fullPage` screenshot does NOT load below-fold `loading="lazy"` images, so masked figures appear as empty frames and look like a broken build. `tests/visual/sweep.mjs` already scrolls and waits before capturing — use the sweep for evidence, never a one-off MCP capture.
24. (`claude-opus-5`) Calibrate every reference image against a DESIGN-SYSTEM CONSTANT before measuring it, not against its own canvas width. `Home2.jpeg` (1600px) and `courses.jpeg` (1296px) both turn out to be ~1:1 with the 1307px canvas — different crops, same zoom — anchored by a known 56u button and a known 1119u content column. Skipping this made two references disagree about heading size by 17%.
25. (`claude-opus-5`) That disagreement was real, not error: the About heading is a DISPLAY size (70.5u) while section headings are 60u. When two references disagree after correct calibration, believe them — they are describing different roles.
26. (`claude-opus-5`) CSS source order bites inside a single appended block: a `figure { margin: 0 }` reset placed after an element's `margin-inline-start: auto` silently cancelled it, stacking two collage images exactly on top of each other. The symptom looked like a missing image, not a layout bug.
27. (`claude-opus-5`) When two measurements of the same token disagree, trust the one corroborated by an INDEPENDENT anchor. The courses heading's line 1 asked for 59.8u and line 2 for 54.5u; line 1 agreed with the card-grid calibration to within 0.3%, so 60u stood and line 2's gap was accepted as a rendering difference in the bronze span. Chasing line 2 would have shrunk every section heading on the site.
28. (`claude-opus-5`) Transcribing a reference's line breaks with `<br>` silently wrecks accessible names unless a real space precedes each one ("Learning the Quranshouldn't depend on"). It recurred across six headings in one pass. `report.json`'s heading outline is the cheapest detector - read it after any pass that adds breaks.
29. (`claude-opus-5`) Section heading sizes are NOT one token. Measured against their own anchored references: About 70.5u (display), Courses 60u, Pricing 51u, Testimonials 48.4u, Blog 46.1u, Teachers 40.6u - and Testimonials and Blog are set in bold SANS, not the display serif. The spread tracks the width of the column each heading occupies.
30. (`claude-opus-5`) Calibrate each reference by a structural invariant and the numbers fall out clean: Teachers.jpeg's content column decomposed to left 268u + gap 51u + cards 800u = exactly 1119u, and pricing.jpeg's rebuilt benefits strip landed on 1119u against the reference's 1120u.
31. (`claude-opus-5`) A change to a SHARED helper (`eqc_teacher_card`, `eqc_trust_tile`, ...) only reaches the page you re-run. Every other page keeps the old markup baked into `_elementor_data` - the /teachers/ page silently lacked a button added to the shared card. Re-run ALL of `tools/pages/*.php` after touching a helper, exactly as §4 gotcha 2 requires after regenerating an inline SVG.
32. (`claude-opus-5`) Elementor widget wrappers carry paragraph margins that stack on top of a card's own flex `gap` - measured 20.8u of dead margin around 56.5u of body text. Compare a widget's outer height to its inner content height to find it; it is invisible in the design and inflates every card on the site.
33. (`claude-opus-5`) `gap: <n>` sets BOTH axes. The courses grid's reference has an 88u column gap but a 17u row gap; using the column value for both added 71u of dead space between rows. Always measure both axes before writing a shorthand gap.
34. (`claude-opus-5`) Section-height RATIOS (each section against the hero) are immune to a reference capture's unknown vertical scale, so they are the reliable way to use a whole-page composite whose absolute scale cannot be trusted.
35. ~~(`claude-opus-5`) **A reference image's pixel width is only the canvas width when its aspect ratio is a screen's.**~~ **PARTLY SUPERSEDED by #41.** The observation was right and the fix was half wrong: the sections really were 1.41-1.48 viewports tall at 1600, but that is a VERTICAL symptom and rebasing the horizontal unit was the wrong lever. Rebasing `--eqc-u` to 1600 without rescaling the values transcribed on the 1307 canvas shrank every section to 69.9% of the viewport.

36. (`claude-opus-5`) **Type and layout cannot share one linear multiplier.** With everything on `--eqc-u`, the H2 was 73.4px over 14.7px body copy at 1600 — a 5.0:1 ratio where healthy editorial setting is 2.5–3:1. That single fact produces both user complaints at once: giant headings burn the vertical budget so nothing fits on screen, and the same multiplier starves the body copy so the content is unreadable. Scaling the unit down fixes the headings and makes the body worse; scaling it up does the reverse. Layout keeps the unit; every type role gets its own `clamp(floor, unit, ceiling)` so it is continuous and floored at every width.
37. (`claude-opus-5`) **A contrast audit is not a legibility audit.** The previous pass reported "72 text styles pass WCAG AA" while ten roles rendered at 7.6–9.4px on a 390px phone — teacher facts and blog dates at 7.6px. 7.6px text passes contrast perfectly. Nothing in WCAG's contrast criteria constrains font size, so a clean contrast run says nothing about whether the text can be read. Measure the smallest *rendered* font size on every route and viewport as its own check.
38. (`claude-opus-5`) **A floor tied to a breakpoint is not a floor.** Both floors in this theme were `@media (max-width: 1100px)` blocks, and both failed on the far side: type had no floor from 1101–1600, and the 44px tap-target floor left every button at 40.6–44px across 1101–1213px. Express a floor in the value — `clamp()` for type, `max()` for boxes — so it holds at every width by construction.
39. (`claude-opus-5`) Absolutely-positioned children of an Elementor card offset from the CONTENT box, so adding card padding moves the decoration and the flow content together and cannot separate two colliding layers. The pricing card's "RECOMMENDED" tab rendered as "…MENDED" behind the medallion; increasing the card's padding moved both and changed nothing. Solve it on the decoration's own `top`/`inset-block-start`, from measured element rects, not by padding.
40. (`claude-opus-5`) Reducing a card's height does not shrink a section whose height is set by a SIBLING column. The teachers card's top padding held ~46px of genuine dead space (89px reserved for a portrait that intrudes 43px), but removing it moved the section by 0px — the 268u aside column beside the cards is the tallest element. Find the binding constraint before optimising anything.
41. (`claude-opus-5`) **Rebasing a proportional unit means rescaling every value transcribed on the old basis.** `--eqc-u` moved from 100/1307vw to 100/1600vw, but all 82 horizontal `calc(n * var(--eqc-u))` values, `--eqc-content-max: 1119u`, the teachers split (268+51+800) and the pricing strip were native pixels measured on Home.jpeg's 1307 canvas. `1119u` silently stopped meaning 85.6% of the viewport and started meaning 69.9% — every section 250px too narrow on each side, which is exactly what the user reported as "squeezed, extra padding left and right". Either rebase the unit AND multiply every transcription by the same factor, or leave the unit alone. Corrects #35.
42. (`claude-opus-5`) The same trap catches the TYPE tokens, because `clamp(floor, calc(n * var(--eqc-u)), ceiling)` rides the unit in its middle term. Rebasing the unit changes every rendered size unless each `n` is divided by the same factor. Floors and ceilings are absolute px and do not move.
43. (`claude-opus-5`) **Section heading sizes are measured per section, and "healthy editorial ratio" is not a reason to override them.** An earlier pass collapsed six measured headings (#29) onto two tokens and compressed them to reach a 2.5-3:1 heading:body ratio. Measured on pricing.jpeg the client's own design sets a 51u heading over a 12.4u list — 4.1:1. The compression left every section heading 26-46% too small. Recover section height from SPACING, never by overriding a measured type size.
44. (`claude-opus-5`) A decoration sized without reference to its container will overflow it. `.eqc-divider-svg` was `width: clamp(180px, 22vw, 240px)` — a bare clamp with no relation to the slot — so the teacher card's divider rendered 240px inside a 183px card and read as a rule running across the gap into the next card. `width: 100%` with the clamp as `max-width` sizes to the slot and keeps the old ceiling for free-standing rules.
45. (`claude-opus-5`) **A modifier must carry the same specificity weight as the rule it modifies.** The base button is written `a.eqc-btn, button.eqc-btn, ...` (0,1,1); `.eqc-btn--sm` (0,1,0) therefore lost every cascade and the "small" button kept the full 53u inline padding — 305px wide inside a 337px column. Modifiers on element-qualified base rules need `a.eqc-btn--sm, button.eqc-btn--sm` too.
46. (`claude-opus-5`) A carousel with every card already visible has `pageCount === 1`: both arrows sit permanently disabled and the dot strip shows one dot. Reviews.jpeg draws no arrows for exactly that reason. The controls still cost their inline padding (22px off each card) and ~100px of vertical gap. Hide them from the paging state, not with a hard-coded rule — they return by themselves when the card count makes paging real.
47. (`claude-opus-5`) Elementor's container gap survives a `display:flex` -> `display:grid` override. The testimonial strip's base rule was a flex row with `gap: 0.4em 1.3em`; re-declaring `display:grid` in a section-scoped rule kept that 1.3em as an 18.8px COLUMN gap, taking 38px off three cells and wrapping every label. Re-declare `gap` whenever you re-declare `display`.
48. (`claude-opus-5`) `tests/visual/sweep.mjs --out` resolves relative to the CWD, not to the script. Run from the repo root, `--out ../../QA/after/x` writes two levels ABOVE the repo and the run looks like it silently produced nothing. Pass a path relative to where you are standing.
49. (`claude-opus-5`) Confirm a difference is a defect before fixing it. The featured pricing card renders its medallion lower than the other three, which reads as the RECOMMENDED tab pushing content down — but pricing.jpeg does the same thing (18 native px). Measuring the reference first turned a "bug" into a 39px refinement.
50. (`claude-sonnet-5`) **A `@media` override placed ABOVE the base rule it overrides loses the cascade at equal specificity.** A new `@media (max-width:640px) .eqc-chip--card { min-height:0; ... }` block was inserted next to the sibling breakpoints, but the base `.eqc-chip--card { min-height: var(--eqc-card-h) }` was defined ~10 lines LOWER — so the base won everywhere and the phones still showed the dead space the fix was for. Put breakpoint overrides after the base declaration, or qualify them harder.
51. (`claude-sonnet-5`) **`filter: drop-shadow()` on an element with low `opacity` renders the shadow multiplied down by that opacity** — `opacity` groups the already-filtered result. A masked corner ornament at `opacity: 0.3` with a `drop-shadow(... / 0.55)` gets an effective ~0.16 shadow and still reads flat. Carry the tint in the paint's own alpha (`background-color: rgb(r g b / 0.3)`), keep element `opacity: 1`, and the shadow renders at full strength — real carved depth.
52. (`claude-sonnet-5`) **A sticky header with an opaque background hides whatever a hero pulls up behind it.** The hero arch was lifted with a negative top margin but stayed invisible until the header's bottom edge, because `.eqc-header { background: var(--eqc-cream-100) }` painted over it. Make the header background `transparent` at rest and restore it on `.is-scrolled` — the page ground is the same cream, so nothing else changes, and the arch tip now rises into the gutter around the floating nav pill (client's Home.jpeg / qa-10092026/5.png).
53. (`claude-sonnet-5`) The About paragraph's em dash was previously recorded as "transcribed verbatim from the reference" (LESSONS-adjacent, `QA/design-review/home.md` A4). The client's 2026-09-10 review asked for **all** em dashes removed for a professional tone. A direct client instruction overrides a reference-transcription decision — the verbatim rule holds only until the client says otherwise.
54. (`claude-sonnet-5`) **An Elementor HTML-widget wrapper made `position: relative` by a `> *` rule becomes the containing block for the absolutely-positioned element inside it — and silently kills a stretched card link.** `.eqc-card--course > * { position: relative; z-index: 1 }` exists to lift real content above a decorative `::before`. But between `.eqc-card` and the `<a class="eqc-card-link" style="position:absolute;inset:0">` sit `.elementor-widget > .elementor-widget-container`, so the rule caught the WIDGET. Its only child is that absolute anchor, so the widget collapsed to zero height and the anchor resolved to **413x0** — a card that looks perfect, builds clean, sweeps clean, and cannot be clicked anywhere. The same rule on `.eqc-card--pricing--featured` displaced that card's medallion by 38px and floated its RECOMMENDED badge 49px clear of the card, which read as three unrelated design bugs. Fix: give the wrapper its own class via `eqc_html( $html, $classes )` (Elementor prints it on the widget) and stretch or neutralise THAT, rather than fighting the `> *` rule. Detect it with `document.elementFromPoint(centre)` — never by reading the CSS.
55. (`claude-sonnet-5`) **An SVG stroke is painted centred on its path, so a path that touches its own viewBox edge loses half its width to the clip.** `keel-arch-frame.svg` was generated with pad 0, and its jambs run along `x=0` and `x=559` for their full height: the verticals rendered at half the crown's weight, which the client reported as "the left and right of the arch frame is thinner". Padding the generated viewBox is only half the fix — scaling the mask back up still left the jambs thin, because the outer half then fell outside the PSEUDO-ELEMENT's box, where there is no background colour to mask. Both boxes have to grow: pad the viewBox by `ceil(strokeWidth/2)` AND grow the masked element by the same ratio (`inset: calc(-pad / h * 100%) calc(-pad / w * 100%)`) with `mask-size: 100% 100%`. Verify by rasterising the mask to a canvas and comparing opaque run-lengths at the jambs and at a near-horizontal point on the crown — eyeballing a 1px difference on a gold hairline is not possible.
56. (`claude-sonnet-5`) **A zero-height flex item still consumes a `gap`.** After neutralising the pricing badge's widget wrapper to `position: static; height: 0`, the featured card's banner and list still sat 9px below its siblings' — the extra (empty) flex child was drawing one 6u gap. Taking the wrapper out of flow entirely (`position: absolute; inset: 0; pointer-events: none`) fixed it and gave the correct anchoring at the same time.
57. (`claude-sonnet-5`) **Re-reading the CSS you just wrote is not verification.** Round 4 of the client review ticked "course cards clickable", "keel arch single even border" and "arch tip over the nav" on the strength of the edits; all three were measurably wrong (links 413x0, jambs 3px vs crown 4px, arch top at y=-40 with its tip off-screen). A full-page sweep passed on all of them, because 0 console errors and no horizontal overflow say nothing about whether a link has area or a stroke has width. Every visual/interaction claim needs its own geometric assertion — `getBoundingClientRect`, `elementFromPoint`, or a rasterised mask — run in the same pass as the claim.
58. (`claude-sonnet-5`) **Two independent "pin to the bottom" rules on the same card produce a void nobody wrote.** A pricing card had `.eqc-pricing-price-divider { margin-block-start: auto }` AND inherited the shared `.eqc-card__foot { margin-top: auto }` convention, inside a `min-height: 343u` card. Each rule is reasonable alone; together they pushed the last two rows to the floor and left **84px of measured nothing** mid-card — the client's "why waste this space". When a card has a min-height, prefer distributing with `justify-content` on the flex container over per-child `margin: auto`, and grep for every `margin-*: auto` a card's children inherit before adding another.
59. (`claude-sonnet-5`) **Re-styling a component without re-checking its base rule leaves a fossil that breaks it.** `.eqc-pricing-badge` began as a diagonal corner ribbon: `width: 8.5rem; transform: rotate(45deg); padding: 0.35em 0`. A later pass converted it to a horizontal pill and overrode the transform, position, padding, radius and font — but not the fixed `width`. A 158px label was then laid out in a 136px box, and `white-space: nowrap` pushed it straight out. When repurposing a component, read the ORIGINAL declaration block end to end and neutralise every property that belonged to the old form; overriding only what looks wrong on screen leaves the rest waiting.
60. (`claude-sonnet-5`) **A derived asset variant inherits transformations you meant for one case only.** The hero's keel frame is deliberately open at the foot (`d.replace(/Z\s*$/, '')` drops the base). When a rounded-foot variant was added for the About contexts, it was generated through the same `.replace()` — so the About arch silently lost its bottom edge too, which the client reported as a missing border. A shape option (`bottomRadius`) and a topology choice (open vs closed) are different axes; keep them separately parameterised rather than letting one code path carry both.
61. (`claude-sonnet-5`) **A compensation constant outlives the thing it compensated for.** `.eqc-arch-media--keel img` carried `mask-size: 95.7066% 96.1844%` to open a cream gap between the frame's TWO gold contours. The frame later became a single line, but the inset stayed — and because the mask is centred, the leftover slack distributed unevenly: the crown nearly touched while the foot stopped 20px short of the jambs' ends, reading as a misaligned photo. Any magic number in a comment that says "because X" is dead the moment X changes; grep for the constant when you change X.
62. (`claude-sonnet-5`) **A section class that only styles is not the same as the markup that fills it.** The home About section carried `eqc-section--ornamented` (which sets `position: relative; overflow: hidden` and layers `> .e-con` above the ornaments) but never called `eqc_section_ornaments()`, so there were no motif spans to layer and the background sat bare against the reference. The class name reads like it produces the ornament; it only prepares for one. When a decorative class relies on companion markup, either emit the markup from the same helper or say so in the class's own comment.
63. (`claude-sonnet-5`) **Elementor's own frontend reset outranks a two-class rule, and it zeroes figure margins.** `.elementor .elementor-widget:not(.elementor-widget-text-editor):not(.elementor-widget-theme-post-content) figure { margin: 0 }` scores **(0,4,1)** — the two `:not()` arguments each add a class's worth of weight. A theme rule like `.eqc-about-collage .eqc-about-collage__main { margin-inline: auto 0 }` is (0,2,0) and loses silently: the computed margin reads `0px` and the figure never moves, with no error anywhere. This is a different failure from LESSONS #26 (which was source order inside our own file) — here nothing in the child theme is at fault. For a `figure` inside an Elementor widget, offset with `left`/`inset-inline-start` on the already-relative element instead of a margin; it is not a property the reset touches. Confirmed by enumerating every matching rule with `CSSRule` and comparing specificity, not by reading the stylesheet.
64. (`claude-sonnet-5`) **One shared drift keyframe cannot serve ornaments anchored to opposite corners.** `@keyframes eqc-drift { to { translate: -16px -10px } }` was applied to every `.eqc-corner-motif`. On a `--tr` motif flush at `top:0; right:0` inside an `overflow: hidden` section, that translate carries the shape up and out — so it spends most of its cycle with a slice clipped off, reading as a broken fragment rather than a corner bracket; the `--bl` motif drifts inward instead, so the pair never matches. Two fixes together: inset each motif from its corner by more than the drift's amplitude, and give each corner its own keyframe drifting along its own diagonal toward the section's middle. Because `translate` is a separate property from `transform`, per-corner drift composes cleanly with the rotations and flips the corner variants already carry.
65. (`claude-sonnet-5`) **A fix for a known trap has to be carried to every instance of that trap, or it is half a fix.** LESSONS #51 (element `opacity` multiplies `drop-shadow` down, so carry the tint in the paint's alpha) was diagnosed and applied to `.eqc-corner-motif` in round 4. Its sibling ornament — the pricing section's `::before`/`::after` corner frame — kept `opacity: 0.5` plus a single shadow for four more rounds, an effective ~0.14 alpha, and the client reported it as flat three times. When a lesson is written, grep for every other selector exhibiting the same pattern in the same pass; a lesson filed against one selector is a lesson half-learned.
66. (`claude-sonnet-5`) **On a PIERCED ornament, depth is a lighting problem, not a cast-shadow problem.** `corner-ornament.svg` is a girih panel: cream tiles separated by fine gold rules, with real holes between them. Stacking dark `drop-shadow`s on it deposits ink *through* every hole, so the cream tiles end up floating on a grey ground — which reads as the TILES being raised, the opposite of the reference, where the gold rules stand proud. The measurement said the change worked (cast shadow 5.6 -> 31.5 luminance units) while the client correctly saw it had got worse. For a pierced shape, use one tight low-alpha contact shadow plus a light bevel, and get the relief from the artwork's own gradients — `contrast()`/`saturate()` sharpen the rules against the tiles far better than a shadow trying to fake them. **A metric that only measures the thing you set out to increase will happily confirm a regression.**
67. (`claude-sonnet-5`) **A repeating `<pattern>` fill does not necessarily put ink where its canvas corner is.** The corner ornaments tile a girih lace from the SVG origin, and their canvases are not a whole number of tiles wide — so the *dense* corner, the one meant to meet the card's corner, landed in a tile void: 7px of empty canvas and alpha 0 at the corner pixel, which reads as the ornament floating away from the card. Aligning a star's CENTRE on the corner is worse (10px gap): the stars are stroked outlines, so their centres are hollow. The phase that works has to be found empirically — sweep every phase, score ink density in the block hugging the corner — and it is **per asset**, because it depends on the tile size: 11/12 of a tile for `corner-motif` (D 33.8), 5/6 for `lattice-corner` (D 72.4).
68. (`claude-sonnet-5`) **A CWD-relative path in a build script fails silently by succeeding somewhere else.** `build-logo.mjs` used `'wp-content/themes/.../logo'` as its output directory and `'tools/graphics/scratch/mark-path.txt'` as its input. Run from `tools/graphics` — where every sibling generator is run from — it created a complete stray `tools/graphics/wp-content/themes/.../logo/` tree, reported every file written successfully, and left the real theme assets untouched. Nothing errored; the regenerated favicon simply never appeared on the site. Resolve build paths from `import.meta.url`, never the CWD (`gen-ornaments.mjs` already did this correctly, which is why only one of the two generators had the bug).
69. (`claude-sonnet-5`) **Generated assets a theme ships are not automatically referenced by it.** `assets/svg/logo/` has held `favicon.svg`, `favicon-32.png` and `apple-touch-icon-180.png` since the logo pipeline was built, correctly sized — and no template ever emitted a `<link rel="icon">`, while WordPress emits its own only when a `site_icon` attachment is set (it was 0). (`claude-opus-5`) **A fix for a known trap has to be RETIRED when a second, better fix removes the trap — or the first fix becomes the next defect.** Round 6's `--_motif-inset` held the corner girih away from the section edge because the single shared drift keyframe then in use carried it outward past `overflow: hidden` and clipped it. 71. (`claude-opus-5`) **A component whose size is a percentage and whose offset is an absolute unit is only self-consistent at the one width you tested it at.** The home teacher card's portrait had `width: 98%` (of the card) but was positioned with `inset-block-start: calc(-142 * var(--eqc-u))` — a viewport-wide clamp that floors at 0.70px below ~915px. Above the floor both quantities scale together and the ratio between them holds; below it the percentage keeps shrinking with the card while the offset freezes, and the two disagree more the further you go. The fix is not a smaller clamp floor (that only moves where it breaks) — it is putting every dependent value on the SAME basis. `margin-block-start`/`padding-block-start` percentages resolve against the containing block's WIDTH by spec (true for every property in that family, "vertical" ones included) — but `top`/`inset-block-start` resolves against HEIGHT, so it can't take the same percentage directly; using `inset-block-start: 0` plus a width-relative `margin-block-start` gets the same effect through a property that actually resolves the way you need.
72. (`claude-opus-5`) **A flex item's un-stretched cross size is its own shrink-to-fit content — `justify-content: center` inside it centers nothing if there's nothing extra to center within.** A `.eqc-slider-dots` strip built in JS and inserted as a sibling inside a flex row (`.eqc-teachers-split`) read as pinned to one side rather than centered under the row. The dots wrapper had no explicit width, so as a default `flex: 0 1 auto` item its outer box was exactly as wide as its own dots — `justify-content: center` had no slack to distribute. The identical component worked fine everywhere else it was already used, because everywhere else it landed inside plain block flow, where a block defaults to its container's full width. `width: 100%` fixed it and is a no-op in the block contexts, which is why the bug was invisible until this specific insertion point.
73. (`claude-opus-5`) **Making a scaled-down copy proportionally correct is not the same as making it look right at that scale.** The teacher card's mobile portrait was fixed to be exactly as proportioned as its desktop original (LESSONS #71) — and was still reported as too big, because the client's actual ask was to match a DIFFERENT, plainer existing component (the `/teachers/` page's own card) rather than a faithfully-scaled render of the more elaborate one. When two components already exist for the same content at two densities, matching the simpler one on mobile (here: scoping the elaborate desktop override to a `min-width` media query so mobile falls through to the plain base rule that was already correct) is smaller and more certain than tuning scale constants on the elaborate one until it happens to look equivalent.

(`claude-opus-5`) **A plain-string grep for a generated filename misses a template-literal name.** A dead-asset audit searched `gen-ornaments.mjs` for the literal `girih-lattice-dense` and found nothing, so the file was assumed to have no generator and was skipped from the cleanup — but the actual code was `save(\`girih-lattice-${name}.svg\`, ...)` inside a `for (const [name, a] of [['fine', 34], ['dense', 52]])` loop, invisible to that grep. 75. (`claude-opus-5`) **`setPointerCapture()` can throw `NotFoundError` for a pointer that is no longer "active" by the browser's own bookkeeping, and an uncaught throw there aborts the rest of the handler.** Confirmed via a synthetic `PointerEvent` test harness (dispatched events don't register as an active pointer, so every capture call threw) — but the same condition is reachable from real input too (the pointer can legitimately go up in the gap between the move that commits to a drag and the capture call inside it). Capture is a nice-to-have for a swipe gesture, not a requirement — wrap it in `try {} catch {}` so a capture failure degrades to "the drag still tracks, just without leaving-the-element robustness" instead of silently dropping the rest of the pointermove handler (the live-transform update that follows it in the same function).
